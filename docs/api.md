# API

Full interactive documentation (request/response schemas, try-it-out) is
generated by Springdoc and served at **`/swagger-ui.html`** whenever the
backend is running (`SWAGGER_ENABLED=true`, the default outside a production
build where you'd set it to `false`). This document is a map, not a spec -
check Swagger for exact field-level shapes.

## Conventions

- **Envelope**: every success response is `{ "data": ... }`; every error is
  `{ "error": { "code", "message", "details": [] } }` (see
  `com.fitnesshub.common.web.ApiResponse` / `ApiErrorResponse`).
- **Pagination**: paginated list endpoints return
  `{ "data": [...], "page", "pageSize", "totalPages", "totalItems" }`
  (`PageResponse`). Default page size is 20; callers can override with
  `?page=&pageSize=` (server-side capped at 100).
- **Auth**: session cookie, sent automatically by the browser once logged in.
  State-changing requests (`POST`/`PATCH`/`DELETE`) need the CSRF cookie
  echoed back as `X-XSRF-TOKEN` - call `GET /api/auth/csrf` once to obtain it.
  See [docs/security.md](security.md).
- **Ownership**: any endpoint that takes a `clientId` (query param or path
  variable) enforces ownership server-side - a client's own ID is used
  automatically if they omit it, and a coach must own the client they name.

## Endpoint index by domain

| Domain | Base path | Notes |
|---|---|---|
| Auth | `/api/auth/*` | register, login, logout, csrf |
| Users | `/api/users/me`, `/api/users/me/password` | get/update own profile; change own password |
| Dashboard | `/api/dashboard`, `/api/coach/dashboard` | role-dispatched client/coach dashboard |
| Exercises | `/api/exercises`, `/api/exercises/{id}/progress`, `/api/coach/exercises` | library + per-exercise progress + custom exercise creation |
| Programs | `/api/programs`, `/api/programs/{id}`, `/api/programs/{id}/assign` | build a training cycle and assign it to a client with a start date (coach-only writes) |
| Clients | `/api/clients`, `/api/clients/{id}`, `/api/clients/{id}/{progress,workouts,nutrition,checkins}` | coach's client roster + per-client views |
| Coach | `/api/coach/clients`, `/api/coach/clients/{id}/{notes,password}`, `/api/coach/conversations` | client creation, private notes, temporary-password reset for a locked-out client, conversation list |
| Workouts | `/api/workouts*`, `/api/sets/{id}` | today's workout, the Mon-Sun week (`/week`), skipping with a reason (`/today/skip`), logging, completion, feedback |
| Weight/Steps/Nutrition | `/api/weight*`, `/api/steps*`, `/api/nutrition*` | log + dashboard + history |
| Goals/Check-ins | `/api/goals*`, `/api/checkins*`, `/api/coach/checkins` | client submits a weekly check-in; coach reads the pending queue and replies |
| Progress photos | `/api/progress-photos*` | upload/list/delete metadata, plus `/{id}/image` for the bytes. Session-authenticated - there is no public URL |
| Feature flags | `/api/features` | which optional integrations (AI, billing) are configured, so the UI can show "coming soon" instead of a dead end |
| Messaging/Notifications | `/api/messages*`, `/api/notifications*` | |
| Analytics | `/api/analytics` | ad-hoc training summary for a date range |
| AI | `/api/ai/fitness-question`, `/api/ai/client-analysis` | see [docs/ai.md](ai.md) |
| Billing | `/api/billing/{checkout,portal,webhook}` | Stripe; no-ops with a clear error until configured |
| Export | `/api/export/{weight,steps,nutrition,workouts}.csv` | premium-gated for clients, always available to coaches |
| Reports | `/api/clients/{id}/report.pdf` | coach-generated PDF progress report |

The shape isn't uniform everywhere a more RESTful arrangement made sense (e.g. workout
history/detail nest under `/api/clients/{id}/workouts` for coach views in
addition to the client's own `/api/workouts`). Swagger UI is the definitive
list.
